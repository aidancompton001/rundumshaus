ЛОВУШКИ, НА КОТОРЫХ ЭТА ЗАДАЧА ПРОВАЛИТСЯ

- Сверка «на глаз» вместо диффа. Тексты немецкие, длинные, отличия в одном слове не видны. Сверять программой
- Сравнение с уже отрендеренным HTML вместо JSON: если текст потерян при верстке, сверка HTML с HTML этого не покажет
- `&nbsp;` и `&amp;` в мокапе против обычных пробелов и амперсандов в JSON — нормализовать обе стороны, иначе получится либо ложное расхождение, либо ложное совпадение
- Немецкие композиты ломают узкие колонки: после подстановки длинных текстов заново прогнать проверку лейаута, а не считать ее пройденной с прошлого раза
- Заявление «все тексты перенесены» без перечисления, что именно считалось «всеми». Реестр обязан называть число и способ его получения

HRC-РЕЕСТР

Завести `verify/hrc_ledger_t010.json`. Каждое утверждение — с исполнимым доказательством: команда, которую можно запустить прямо сейчас и получить тот же ответ. Обязательно среди утверждений:

- число текстовых полей в источниках и как оно получено
- число точек `data-cms` в мокапе и как оно получено
- результат посимвольной сверки каждой из 5 услуг
- список непереносимых полей с причиной по каждому
- результаты всех пяти инструментов верификации
- статус живого превью и живых сайтов сервера

Требования к доказательствам: пруф обязан уметь провалиться. Проверить это мутацией — испортить одно поле во временной копии и убедиться, что пруф краснеет. Пруф, который зеленый при испорченных данных, не пруф.

Прогон: `py verify/hrc.py verify/hrc_ledger_t010.json` — P должно быть 0. Ревью Ланды обязательно, `require_landa` не выключать.
