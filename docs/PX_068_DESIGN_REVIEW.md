## 1. БЛОКИРУЮЩИЕ ОШИБКИ

### E1 — Fine-grained PAT для Кевина технически НЕВОЗМОЖЕН

Дизайн (раздел 2.3): «Kevin генерирует fine-grained PAT, scope: только этот repo».

**Факт GitHub:** fine-grained токены выпускаются только под resource owner =
собственный аккаунт или организация, в которой состоишь. Репо принадлежит
**личному аккаунту `aidancompton001`**. Kevin (`rundumshaus-littawe`) — коллаборатор
(проверено: `gh api .../collaborators` → оба аккаунта), но коллаборатор личного
чужого репо **не может** выпустить fine-grained token на него.

**Реальные опции:**
| Опция | Цена вопроса |
|-------|--------------|
| A. Classic PAT (scope `repo`) | Работает сразу, но токен даёт доступ ко ВСЕМ репо Кевина (у него их мало — риск приемлемый) |
| B. Перенос репо в организацию | Fine-grained станет возможен; миграция Pages/Actions/secrets — ~1ч работы + риски |
| C. OAuth (Phase D) сразу | Кнопка «Login with GitHub», нужен Cloudflare Worker + OAuth App |

**Рекомендация ревью:** A для запуска (с письменной фиксацией риска) ИЛИ сразу C.
Вариант дизайна «fine-grained» — вычеркнуть, он не существует для нашей топологии.

### E2 — Content-coupled тесты заблокируют деплой правок Кевина ⚠️ САМОЕ КРИТИЧНОЕ

**Факт CI:** `deploy.yml` на push в master запускает `lint → test → build`
(строки 40–46). **Тест упал → деплой не происходит.**

**Факт тестов:** тесты хардкодят ровно тот контент, который Kevin будет менять:

| Файл:строка | Хардкод | Что сломает |
|---|---|---|
| `smoke.test.tsx:38` | `/Alles rund ums Haus/` | Kevin меняет Hero-заголовок |
| `data.test.ts:29` | nav `toEqual([5 точных labels])` | Kevin меняет пункт меню |
| `services.test.tsx:121-125` | 5 literal-текстов описаний услуг | **Kevin как раз собирается прислать 4 новых текста услуг!** |
| `services.test.tsx:166` | `/Willkommen bei Rund ums Haus Littawe/` | Kevin меняет Über-uns |

**Сценарий провала:** Kevin меняет описание Gartenpflege в CMS → commit → deploy.yml
→ `services.test.tsx:122` падает → деплой молча отменён → Kevin ждёт, на сайте
ничего → «admin panel kaputt» → доверие потеряно.

**Обязательный пре-реквизит (новая фаза A0):** декаплинг content-тестов —
сравнивать рендер с **источником** (`homepage.json` / `services.json`), а не с
литералами. Структурные проверки (2 CTAs, 5 услуг, поля не пустые) остаются —
они как раз защищают от поломок Кевином.

### E3 — Image-pipeline: загрузка картинки через CMS даст битые/устаревшие изображения

**Факт кода:** `getImageUrl.ts:27-30` — `toResponsiveWebpSrcSet("/images/about.png",
[400,800,1200])` строит URL `about-400w.webp` и т.д. Используется в
`AboutSection.tsx:89` и `ServiceOverview.tsx:44`. Варианты генерируются **вручную
sharp-скриптом** (как я делал для всех hero).

**Два сценария провала Кевина:**
1. Заливает картинку под **новым именем** → `-400w.webp` вариантов нет → `<source>`
   404 → `<picture>` НЕ фоллбэкает на `<img>` при 404 источника → битая картинка.
2. Перезаписывает **то же имя** (`about.png`) → старые webp-варианты остаются →
   посетители видят СТАРУЮ картинку (браузер берёт source), Kevin — недоумевает.

**Решения (выбрать одно):**
| Решение | Сложность |
|---------|-----------|
| A. CI-шаг: на изменения в `public/images/**` запускать sharp-генерацию вариантов автоматически | ~1-1.5ч, надёжно, рекомендую |
| B. Упростить компоненты до одного `<img>` без вариантов для CMS-managed картинок | Потеря LCP-оптимизации (мы её специально делали в PX-047!) — НЕ рекомендую |
| C. Исключить картинки из CMS-scope Phase A | Kevin явно просил «Bilder ändern» — обходит требование |

## 2. ПРОПУСКИ (G1–G9)

| # | Пропуск | Риск | Фикс |
|---|---------|------|------|
| G1 | **Field-dropping footgun**: если config.yml объявляет не все поля JSON, save через CMS может выбросить необъявленные (`icon`, `subPage`, `detailImage`…). Sveltia заявляет сохранение unknown fields (в отличие от Decap), но это НЕ проверено | Молчаливая потеря данных | Round-trip тест (см. §4.2) + объявить ВСЕ поля |
| G2 | **Версия Sveltia не запинована** (`unpkg/@sveltia/cms` = latest). Это код с write-доступом к репо в браузере Кевина — supply-chain | Авто-апдейт может сломать/скомпрометировать админку | Пин точной версии ИЛИ self-host JS. Сделать ОБЯЗАТЕЛЬНЫМ, не «запасным» |
| G3 | **og:title/og:description** не упомянуты — override должен течь и в Open Graph, иначе title в Google ≠ title в WhatsApp-share | Несогласованность | resolveMeta → generateSEO целиком (он уже строит og) |
| G4 | **CDN-кеш 10 мин** (max-age=600) не в user journey. Kevin СЕГОДНЯ уже путался с кешем («Scheiße irgendwie läuft das gerade nicht») | «CMS не работает!» | В journey: «после Speichern: 2-3 мин build + до 10 мин кеш; жёсткая перезагрузка» |
| G5 | **Classic PAT default expiry 30 дней** — через месяц вход умрёт | «Сломалось через месяц» | Инструкция: no expiration / 1 год + заметка в календарь |
| G6 | **{city}-паттерн vs tier-логика `safeTitle`**: наш код режет title для длинных городов (Neuenkirchen-Kreis-Steinfurt = 28 симв.). Паттерн Кевина обойдёт guard → 80+ симв. titles | SERP-обрезание на длинных городах | Документировать: override отключает tier-guard (просто) ИЛИ сохранять guard поверх паттерна (сложнее). Решить ДО реализации |
| G7 | **Editorial workflow в Sveltia не поддержан** → каждый Save = прямой commit в master = мгновенный деплой. Без черновиков/ревью | Kevin не может «сохранить черновик» | Зафиксировать как осознанное ограничение в инструкции Кевину |
| G8 | **Немецкий UI**: labels коллекций/полей не спроектированы на немецком. Kevin не говорит на dev-английском | UX-барьер | В config.yml: все label/hint на немецком, locale: de |
| G9 | **JSON-валидация в CI** — сейчас только `JSON.parse` (deploy.yml:37), без схемы. CMS пишет валидный JSON, но схему никто не проверяет | Сломанная структура пройдёт parse | Лёгкая schema-валидация (zod) для homepage/services/meta-overrides в CI |

## 3. Что дизайн сделал ПРАВИЛЬНО (сохранить как принципы)

1. **Fallback-first**: пустой/битый override → текущая кодовая генерация. Сайт неубиваем вводом Кевина. ✅
2. **Шаблон-вместо-490-правок**: 5 паттернов услуг с `{city}` вместо 490 ручных правок. Правильная абстракция. ✅
3. **Изоляция `/admin/`**: noindex, не в sitemap, отдельный bundle → ноль влияния на SEO/перф публичного сайта. ✅
4. **Git-revert откатываемость** каждой правки. ✅
5. **Отказ от WordPress** — обоснован корректно. ✅
6. Структурные тесты данных (data.test.ts «has 2 CTAs», truthy-поля) — это и есть защита от Кевина, их сохранить при декаплинге. ✅

## 4. Тесты и скрипты (конкретный план)

### 4.1 Phase A0 (НОВАЯ, до CMS): декаплинг content-тестов
- `smoke.test.tsx:36-52` → сравнивать рендер с `homepage.json` (импорт), не с литералом
- `data.test.ts:26-37` → структура nav (length>0, label/href truthy), не точные labels
- `services.test.tsx:118-126,163-167` → описания из `services.json`, не литералы
- Прогон: `npm test` зелёный ДО и ПОСЛЕ симуляции правки контента (sed-замена текста в JSON → тесты всё ещё зелёные → откат)

### 4.2 Новые скрипты верификации (`site/scripts/admin/`)
| Скрипт | Что проверяет |
|--------|---------------|
| `validate-cms-config.mjs` | YAML парсится; каждый collection.file существует; **каждый ключ целевого JSON покрыт полем в config** (anti-field-drop); media_folder существует; версия Sveltia запинована в index.html |
| `roundtrip-sim.mjs` | Симуляция Save: читает JSON → оставляет только declared fields из config → diff ключей → FAIL если что-то теряется |
| `meta-overrides-validate.mjs` | Схема overrides; для services.* паттерн содержит `{city}`; длина title-паттерна с самым длинным городом (28 симв.) ≤ 70 |
| `images-variants-check.mjs` | Для каждого образа, на который ссылается `toResponsiveWebpSrcSet`, существуют все `-NNNw.webp` варианты (ловит E3 после любой загрузки) |

### 4.3 Unit (vitest)
- `resolveMeta`: override применяется / пустой → fallback / битый JSON → fallback (try-catch) / `{city}` подстановка / длинный город
- Пустой `meta-overrides.json` → snapshot title/description главной **идентичен** текущему (регрессия = 0)

### 4.4 jsdom (post-build)
- `out/admin/index.html`: `noindex` присутствует; script src содержит запинованную версию
- Главная: og:title === <title> при override
- 5 city-страниц: подстановка `{city}`-паттерна корректна

### 4.5 E2E user journey (до передачи Кевину)
Sveltia поддерживает **local backend** (работа с локальными файлами без GitHub) —
прогнать 3 сценария Кевина локально, без токена:
1. **Текст**: /admin/ → Startseite → правка Hero → Save → файл `homepage.json` изменился → `npm run build` → jsdom: новый текст в `out/index.html`
2. **Картинка**: upload → файл в `public/images/` → `images-variants-check.mjs` показывает, что требуются варианты → CI-шаг генерирует → build → srcset валиден
3. **Meta**: SEO-коллекция → правка title главной → `meta-overrides.json` изменился → build → `<title>` и `og:title` изменились
Каждый шаг — скриптуемый (bash + node), войдёт в `scripts/admin/e2e-journey.sh`.

### 4.6 Канарейка (расширение существующей)
- `canary-verify.mjs`: добавить проверку `/admin/` → HTTP 200 + noindex + версия запинована
- Существующие 5 услуг — без изменений (meta-override при пустом файле ничего не меняет — подтверждается канарейкой)

## 6. Скорректированный pipeline

```
A0  Декаплинг content-тестов + schema-валидация (zod)        ~1.5ч  ← НОВОЕ, без этого нельзя
A   Sveltia CMS (пин версии, немецкие labels, ВСЕ поля)       ~2-3ч
A+  CI-шаг sharp-вариантов картинок                            ~1-1.5ч ← НОВОЕ (E3)
B   meta-overrides статичных (через generateSEO, incl. og)     ~2ч
C   meta-паттерны 5 услуг (+ решение G6 по guard)              ~2ч
V   Скрипты §4.2 + E2E local journey §4.5 + канарейка          ~2ч
D   (опц.) OAuth                                               ~2ч
─────────────────────────────────────────────────────────────
Итого без D: ~10.5-12ч (дизайн оценивал 7-9ч — недооценка ~30%)
```

**Цена пересмотр:** при ~150-200€ за 7-9ч — для 11-12ч честнее ~200-250€, либо
резать scope (без A+ → картинки не в CMS Phase 1).
